# Task: Initialize PS2-to-PC Decompilation Port Project

You are a senior C++ engine developer, reverse engineer, and software architect.

## Project Goal

Initialize a long-term PS2-to-PC native decompilation port project.

The technology stack is:

- **Ghidra** — PS2 Emotion Engine (MIPS R5900) reverse engineering
- **GhidraMCP** — AI-assisted reverse engineering integration
- **OpenAI Codex** — C++ development, analysis, documentation, and testing
- **C++17 or C++20** — Recovered original game and engine logic
- **Godot 4.x** — Rendering, audio, input, window management, and platform integration
- **GDExtension / godot-cpp** — Native C++ integration
- **CMake** — Native core library and test builds
- **Git** — Version control
- **GitHub Issues** — Long-term task tracking

The objective is to preserve original PS2 game logic wherever possible while replacing PS2-specific platform functionality with Godot-based implementations.

This is a long-term reverse engineering project that may require hundreds of development sessions.

**Important: Do not attempt to reverse engineer or port the actual game yet. This task is strictly for project initialization.**

## 2. Architecture Requirements

Design the project around three independent layers:

### Layer A: Recovered Game Core

- Pure native C++.
- Independent from Godot.
- Contains recovered PS2 game logic.
- Includes physics, AI, game state, world management, and other recovered systems.
- Preserves original behavior wherever possible.
- Every recovered function must be traceable to its original ELF address and binary version.

### Layer B: Platform Abstraction

- Provides interfaces for rendering, audio, input, filesystem, timing, and platform services.
- Keeps platform-specific implementations separated from game logic.
- Must allow unit testing without running Godot.

### Layer C: Godot Integration

- Uses GDExtension and godot-cpp.
- Connects the recovered game core to Godot.
- Godot handles rendering, input, audio, and window management.
- Original game logic remains authoritative for gameplay behavior.
- Avoid replacing recovered physics with Godot physics unless explicitly decided.

Document the dependencies and ownership responsibilities between these layers.
