## E0052D02: framebuffer precision hypothesis rejected

The hypothesis that a 16-bit main framebuffer reduces destination alpha192 to128 is unsupported by the recovered initialization. Retail `001064C8` sets main targets15 through21 to FrameMode0, FrameWriteMask0 and FBA0. Only environment-map target14 has FrameMode2/FBA1. Debug type `eRenderTarget` identifies FrameMode at+0x24, FrameWriteMask at+0x2c and FBA at+0x4c; the value at+0x6c is background colour, not the framebuffer mask.

Debug `eSwapScreenBuffers` entry `00107E68` selects main targets15/16 (FULLHEIGHT),16 (FULLHALFHEIGHT),20/21 (QUINCUNX), or18/19/20 (HALFHEIGHT). Debug `eRenderTarget::UpdateGifTags` `001058D8` packs FrameMode directly into the GS FRAME PSM field and makes relative targets inherit MainDrawContext FrameMode. Debug `eDisplayFrame` `00112C60` changes main ZBufferMode for in-game drawing; it does not change FrameMode. Thus this recovered normal path is PSMCT32 with writable8-bit destination alpha. No reduction of Roadshine intensity is justified by this hypothesis.

Raw read-only captures: `retail-target-initializer.json`, `type-eRenderTarget.json`, `debug-main-context-selection.json`, `debug-update-gif-tags.json`, `debug-display-frame.json` under `local/task0052`.

## E0052D04: real road C3 arithmetic on GPU

`roadshine-alpha-fixtures.json` contains original Track11 solid RD_SECTION10_CHOP1 first indexed vertex and its quantized native normal, material blocks, original per-instance light context, six chosen camera positions and CPU oracle results. They were generated by `reverse/task0052/generate_roadshine_fixtures.cpp` using current Scene-owning translation units compiled privately, then `reflection_002A7F90` and `alpha_002A6F78`. Nine significant decimal digits retain float32 inputs. The first four material vectors drive C3; the retained second four are the original environment context, not substituted coefficients.

The asset-free GPU fusion smoke extracts the shared `vu_reflection`, `vu_bit_affine`, `hp2_track_alpha40` functions and evaluates them on these real inputs. All six observed alpha bytes match the CPU oracle:20,20,21,91,20,20 (`local/task0052/fusion-c3-gpu.log`). This exercises float-bit reinterpretation, affine power and FTOI-style truncation; it is not a constant-alpha fusion fixture. It does not yet certify full vertex upload/interpolation or the complete original-console frame.

The host source supplies original normal.xyz through CUSTOM0 RGBA_FLOAT and deliberately zeroes componentw; the shared vertex shader reads only CUSTOM0.xyz. C3 replaces alpha independently of packed vertex COLOR, so Godot COLOR transfer cannot change C3 alpha. The RGB lighting/texture path remains a separate check.

The postprocess worker independently identified an actual TASK0051 raw-depth helper defect. Fresh Retail0010AC50 decompilation confirms the normal geometry GIF register list `0x412` (ST=2, RGBAQ=1, XYZF2=4), repeatedly written to the ordinary geometry tags. Although VU preserves float z bits, PACKED XYZF2 extracts z bits4..27 before writing ZBUF. Therefore `screen_depth_to_gs` and shared GLSL `hp2_track_gs_depth` now return `(floatbits>>4)&0xffffff` for the supported normal PSMZ32/24 paths. Original range endpoints `0x40000010` and `0x40802000` become GS depths1 and0x080200. Private `track_effects_tests` passed with the corrected expectations. This changes raw depth supplied to original postprocess reconstruction; host perspective ordering and Roadshine RGB fusion are unaffected. Historical TASK0051 pins remain unchanged; this requires the explicit TASK0052 successor review.
