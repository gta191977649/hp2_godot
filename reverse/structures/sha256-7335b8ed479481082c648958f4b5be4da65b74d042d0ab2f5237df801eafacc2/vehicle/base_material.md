## Normal and reflected view-vector preparation

Original packets optionally contain VIF V4_8 command6Exx805C after the packed color stream. It unpacks signed normal bytes as groups of four X, four Y and four Z lanes. Upload count is3*ceil(vertex_count/4). Scalar normal conversion at PC2D1..2D7 is ITOF0 then multiplication by exact immediate bits3C010204 (approximately1/127). No host normalization is substituted. The checked native reader exposes raw_normal, normal and has_normal. Original unlit strips lacking flags0x1C0 may proceed directly to MSCAL14000000 without a normal block; the reader preserves that absence.

PC2C4..307 loads position P and uploaded camera C at VU368. For each vertex, N is the converted normal, D=P-C, t=sum(Di*Ni+Di*Ni) in source accumulation order, R=D-N*t. Compute r2=sum(Ri*Ri). The original ITOF0 converts the signed integer representation of float bits(r2) to a numeric float. Apply affine(-.5,1597031552), FTOI0 back to a signed integer, then reinterpret its bits as float. Multiply R by that approximate inverse length. This is the source algorithm; replacing it with normalize()/inversesqrt() changes behavior.

## Base RGBA pipeline PC332..3D9

Inputs: material vectors VU350..353 (M0..M3); light vectors VU35C..362 (L0..L6). L0..L2 are three RGBA coefficient vectors, L3 is ambient, L4..L6 are direction rows. The original main path copies354..357 to350..353 before this base stage. CPU0010A438 commandcase2 uploads descriptor+C0 when modeglobalGPAC50 iszero, or+100 otherwise; normal static frontend mode selects the first block. This selection must not be guessed from the descriptor layout.

For each light j=0..2, d[j]=max(0,L4[j]*N.x+L5[j]*N.y+L6[j]*N.z). Start s[j] similarly using R; clamp it to M0.z. The power coefficients are M0.xy when final render flag4 isclear, and M3.xy when flag4 isset: original conditional PC34E skips or executes PC358 MOVE.xy. The power operation is ITOF0 on float bits(s), affine with those coefficients, FTOI0, then reinterpret asfloat. It is not host pow().

RGB before packed-color modulation is L3.rgb + sum(Lj.rgb*M1.rgb*d[j]) + sum(Lj.rgb*M2.rgb*power[j]), preserving the original diffuse-then-specular accumulation order. Flag4-clear alpha is L3.w + sum(Lj.w*d[j]); the original MUL.xyz leaves these light alpha lanes unchanged and the specular alpha lanes arezero. Flag4-set alpha is M3.z + M3.w*power[0]; diffuse alpha lanes arezero. The flag originates from texture byte+0x74 through0010DD58 and can also be present in final strip/caller flags; field meaning remains unnamed.

VIF V4_5 packed color unpacks low5 toR, next5 toG, next5 toB with each shifted left3, and highbit toA=128. For base-lit vertices, each computed RGB component is multiplied by 1+(unpackedRGB-255)*M0.w. Source packed alpha is not multiplied into the lit alpha. Clamp all four channels to0..255, then FTOI0 truncation writes RGBAQ. Unlit strips keep the original unpacked color instead of running this lighting routine.

## Limits

Host float arithmetic and GPU backend rounding have not been verified against VU hardware. The opcode interpreters are bounded static instruction projections, not a validated general VU emulator. Dynamic lighting-route changes, alternate material mode, extra reflection passes, original clipping precision and full runtime equivalence remain separate work. No generic Godot light, guessed Phong exponent or host normalization is used to fill these gaps.

## GS transparency range and host boundary

E-0033-G05 range regression: the original Default/Window911 normal descriptor has alpha endpoints20/128, but its alpha power coefficients use scale8 and amplitude1.6. At reflected-direction dot1, the retained affine-bit operation produces power approximately1.6 and final vertex alpha192. The VU clamp is255, not128. With texture alpha127, MODULATE gives GS source alpha floor(192*127/128)=190; ALPHA44 therefore has coefficient190/128, exceeding unity. The native base test preserves this case. This demonstrates a reachable algebraic input, not a claim that a particular camera/model vertex has been observed at that input.

A conventional host source-over factor clamped to[0,1] cannot reproduce that GS equation. Silently clamping is not a supported original rendering branch. A screen-texture destination-read implementation using only the opaque snapshot is also insufficient for overlapping transparent primitives: each source primitive requires the framebuffer destination after all preceding accepted draws. Exact support requires an ordered destination-read compositor with current color/depth state, or an equivalent lower-level backend. A bounded native adapter can instead evaluate source vertex alpha per camera, retain screen-linear interpolation, combine it with the actual texture alpha range and explicitly reject unsupported coefficients before drawing. That boundary is a host limitation, not a newly inferred original alpha rule.

Pinned Godot4.4.1 implementation guidance (host evidence only): `drivers/gles3/rasterizer_scene_gles3.cpp` around2790..2819 implements spatial mix as SRC_ALPHA/ONE_MINUS_SRC_ALPHA, add as SRC_ALPHA/ONE, sub as FUNC_REVERSE_SUBTRACT with SRC_ALPHA/ONE, mul as DST_COLOR/ZERO and premultiplied as ONE/ONE_MINUS_SRC_ALPHA. There is no exposed arbitrary spatial blend equation in this path. Reverse subtraction is destination minus source; substituting it does not provide the negative destination coefficient required by GS alpha above128.

Host raw-color handling: original GS RGB bytes remain encoded values through texture sampling and blend arithmetic. The bridge sampler must not use `source_color`. Pinned `drivers/gles3/shaders/scene.glsl` converts ALBEDO from sRGB to linear and then the unshaded result back to sRGB; `drivers/gles3/rasterizer_gles3.cpp` disables GL_FRAMEBUFFER_SRGB. Consequently the Compatibility framebuffer blend operates on encoded values, while this shader's OUTPUT_IS_SRGB branch supplies those values directly. Other Godot renderers require a separate verified blending strategy. This is color-space handling for the port, not original PS2 evidence.

Original CPU0010DD58 preserves raw strip flags (except its documented caller clear-mask), and00104A20 queues the resulting16-bit flags. 0010A438 case0 writes VIF ITOP as0x04000000|flags.
