# E0065H01 - Track11 host matrix batching and diagnostics

User-authorized port adapter optimization, not original-game reconstruction or PS2 verification. Native command selection/order, LOD, local lighting, RNG and effect state remain authoritative.

A conservative planner joins only adjacent unlit Copy commands with equal texture/material/effect/light state, native LOD and unambiguous section ownership. Alpha producers, environment/fusion passes and depth bias are barriers. A 65536-vertex host chunk cap and existing 64 MiB unreferenced LRU bound transport. Raw original local position/CUSTOM0 normal/UV/colour/index order are retained. Per-vertex CUSTOM1..3 carry original host matrix rows; the shader evaluates MODELVIEW_MATRIX from VIEW_MATRIX and those rows. CPU world positions are used only for conservative bounds. Matrices participate bitwise in cache identity; baked/raw variants have separate node identities. The encoded depth proxy reuses the same mesh and vertex shader.

CPU pretransformed geometry was rejected: the third dense heading had 39 colour pixels and one depth pixel differ. GPU matrix attributes passed seven Track11 1080p dense/nearby views and three marker-offset views, including combined resource caches. Track24 explicit opt-in still failed at marker offset50; it is excluded from the promoted default. Original MultiMesh remains off. Enabling the opaque queue failed the first dense view and remains off.

Matrix batches in reflection capture or while a car visual consumer is attached changed atlas pixels. The final path falls back to original submissions whenever visual_state_valid is true and in all capture views. Viewer-to-real-car transition and four 1080p atlas/colour/depth fixtures pass with fallback. Default optimized profile enables the candidate only for Track11; explicit world_batches=true is an experimental opt-in for other tracks. Nonidentity renderer owners and static LOD inspection also retain baseline.

Diagnostics sample engine last-rendered-frame viewport visible/shadow/canvas counters and dimensions at one in six frame-post-draw callbacks only when expanded. Export records full camera basis, FOV/aspect/clip planes, backend, controls, native estimates and renderer counters. Disabled viewport counters may be stale and zero may be unsupported. Shared particle draws are not falsely attributed as isolated GPU draws. Snapshot restore recovers camera/control state, not particle/history replay. No per-frame GPU image readback is added to normal use.

All30 tracks have CPU-only on/off census coverage (60 rows), not GPU coverage. Compatibility/Mobile/Forward+ each pass their own baseline/candidate dense comparisons, but backend outputs differ and no reliable timing winner was measured. Compatibility remains default. No FPS, P95 or exact-screenshot-heading claim: the screenshot supplied position only.
