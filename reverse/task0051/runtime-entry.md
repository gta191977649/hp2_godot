# E-0051-U01: independent single-car runtime entry

This is port orchestration, not a recovered Race coordinator, original game-flow transition, AI or race rule implementation. Original vehicle algorithms and the native Session/NativeBackend remain unchanged. Debug NFSHP2.ELF remains the driving authority; Retail track data and render recovery retain their existing version boundary.

The independent entry is `res://scenes/race_scene.tscn`, script `res://scripts/runtime/race_scene.gd`. Arguments `--track=<original catalogue ID>` and `--car=<original catalogue CODE>` select original resources, default11/ELISE. It directly instantiates common Ps2TrackRenderer, Ps2VehicleRenderer and Ps2DrivingRuntime. It does not instantiate TrackViewer, CarViewer, asset_viewer.gd or driving_lab.gd. Reusable input/skid upload helpers are presentation adapters without viewer ownership.

Ps2DrivingRuntime is the existing driving boundary extracted from Ps2DrivingLab: one core Session, NativeBackend, original geometry/CV lookup, material table, wheel publication and skid publication. It adds a virtual requests_enabled gate defaulting true. Ps2DrivingLab inherits that implementation and overrides the gate with HP2_DEBUG_BUILD, preserving the debug-only viewer entry. There is no new vehicle integrator, grip model or Godot physics path. Native algorithm bodies are not changed by the extraction.

Loading selects the exact catalogue vehicle resource path and skin, pumps common render upload incrementally, and waits for both original render resources. Simulation load_config/set_track binds original start and topology; it must publish real_track plus complete body and wheels before activation. Missing data remains an error, with no synthetic plane success. Startup failure releases partially loaded resources. A running native failure pauses and retains the last valid display with an explicit diagnostic.

Runtime process supplies semantic controls to the existing core, applies absolute body/wheel publication, then updates the camera and shared renderers. Track camera updates are required each frame for facades/material camera context. Camera follow distance and pitch remain explicit port presentation choices; horizontal FOV uses E-0050-U02. Runtime has no synthetic floor/grid or replacement road. Focus loss clears controls and pauses; regain resumes while discarding the first elapsed frame. Restart and frontend exit release resources; re-entry constructs a fresh session.

Validation: private C++ syntax checks passed for the common boundary and thin wrapper under HP2_DEBUG_BUILD=1 and=0. Godot script parse passed. `race_scene_smoke.gd`, enabled by `--race-runtime-smoke`, tests direct common-class instances, original displayed track/native car state, engine projection, W input reaching native simulation, focus pause/resume, invalid track failure, recovery, actual frontend exit and independent runtime re-entry. Host integration is not original-runtime Verified equivalence.

Asset-free `track_fusion_gpu` reads exact shared hp2_framebuffer_rgb, hp2_track_fused40_increment and hp2_track_fused40_copy function text from maintained shader sources. Thus tested fusion arithmetic, encoding and additive destination byte domain agree. This does not certify the entire generated track shader, texture sampling, plain non-fused above-unity alpha or every GS destination-read route. Capture log: local/task0051/track_fusion_gpu_smoke.log. No shared build was run for these private tests.
