## Confirmed findings

0011DC80 allocates 0x930 bytes with the exact label at 002ACC20 and passes the result as argument 1 to 0011E860. 0011E758 repeats allocation and passes a null argument 3 for the frontend representation. The initializer stores argument 3 at +0, argument 2 at +4 and the selected 0x560-byte car-info row at +8.

Geometry state spans 24 bytes. Body states start +0x40,+0x58,+0x70,+0x88. The constructor formats prefix from car-info+0x20 with 0032FC98 `%s_%c`, letters A/B/C/D. If car-info+0x538 == 2, letters become A/A/B/C. The separate conditional format 0032FC90 `%s_%c%d` requires config bytes+4 and+7 and applies only to the first two states; this dynamic/damage variant is outside the static slice.

Tire states are +0xa0,+0xb8,+0xd0,+0xe8,+0x100,+0x118. Names at 002ACC40..002ACC90 are exact `%s_TIRE_FRONT_A/B/C` and `%s_TIRE_REAR_A/B/C`. In type2, front C becomes front B and rear C becomes rear B. If a rear lookup is absent, constructor retries its corresponding front lookup. Brake states +0x160/+0x178 similarly fall back rear to front. Wiper states +0x190/+0x1a8, mirrors +0x1c0/+0x1d8, plates +0x1f0/+0x208 are separately bound. Scuffs, dashboard geometry, blur and shadows exist but are excluded.

The native overload returns binding descriptions only. No full constructor, object layout, lifetime, texture patching or ABI is implemented.
