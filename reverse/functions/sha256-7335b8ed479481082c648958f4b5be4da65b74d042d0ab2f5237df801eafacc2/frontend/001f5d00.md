## Confirmed findings

Read from the listing, because the decompiler lost the R5900 argument order. FUN_001F5D00(a0 = block, a1 = type): `bne a1,zero` then `lw v0,0x8(a0)`; `bne a1,v0(==1)` then `lw v0,0x4(a0)`; otherwise `li v0,0x1`. So type 0 reads block+8, type 1 reads block+4 and anything else answers 1. FUN_001F5D28 is the writer and its first instruction is `lw v1,0x0(a0)`: it selects on the block s own stored type at block+0, NOT on its `a1` argument, even though its only caller passes the tree s type there. FUN_001F5D50 is two instructions, `sw a1,0x0(a0)` and `jr ra`: it sets that stored type. With block = 0x002FC1B4 this makes profile+0x164 the current tree type, profile+0x16C the last selected event number for tree type 0 and profile+0x168 for type 1.
