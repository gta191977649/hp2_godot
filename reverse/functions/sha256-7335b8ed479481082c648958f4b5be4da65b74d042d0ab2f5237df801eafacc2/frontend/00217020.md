### TASK-0021 addition (E-0021-22, E-0021-25)

Read in full, because this function is the second half of why selecting Championship or Ultimate
Racer did nothing. It allocates a 0x1C-byte object from the pool named `tExitScreenAnimation`
(string 0x002BC528), constructs it with `FUN_002490D8(animation, screen, class_name, 1)` -- the
same `Type_002490D8` the port already implements for the Options exit -- and stores it at
`instance+0x270`, which is the field FUN_002174A0 tests at its top and feeds to FUN_00249128 while
it is set. It then looks MI_UNDERSCORE (0x32C91DAE) up with FUN_00144140 and calls
`FUN_00248C60(widget, 650.0f, animation+0x10, animation, 0x97BF4B25, 0x32C91DAE)`.

So **the mode-select screens never switch screens directly**: the switch happens only once that
animation finishes. A caller that activates an item and does not tick never arrives, which is
exactly how the port's own test was passing while the feature was broken.

The two floats the twins pass, `gp-0x6AC8` for this one and `gp-0x6AC4` for FUN_002176D8, are both
**650.0f** -- the same x=650 endpoint the recovered exit path already uses, so the argument is a
target position, not a duration. `FUN_00248C60` is called here with six arguments and in the
Options path with four as the port models it; the two call shapes were not reconciled, so the port
drives its existing `Type_002490D8` rather than asserting one signature. The 0x97BF4B25 immediate
is unidentified.
