## Unresolved questions

Why `functions get` reports `end_address: 001e3dbf` (a ~465KB span) for this entry when the
decompiler returns a clean 312-byte body is unresolved -- this looks like a Ghidra function-record
bookkeeping artifact (possibly an orphaned/merged basic-block range) rather than real code, but
that has not been independently confirmed (e.g. by inspecting what, if anything, occupies the
rest of the reported span). Do not reuse the old "~465KB envelope, likely New Main Menu's own
update/tick function" hypothesis from the superseded E-0011-17 entry; it is now considered
disproven; the real update/tick logic for a sustained "browsing the menu" state (if any exists
outside `GAMEFLOW_STATE_IN_FRONTEND`'s immediate pass-through to `GAMEFLOW_STATE_LOADING_TRACK_SPECIFIC`)
was not located this session. `FUN_0016c3a8`, `FUN_001aec90`, `FUN_0016d0a0`, `FUN_0016bde8`, and
the `DAT_0031a8b0`/`DAT_0031a8b4` globals were not decompiled/traced this session.
