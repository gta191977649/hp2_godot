## Confirmed findings

The front-end movie's per-frame tick, and the answer to whether the movie loops. When manager+0x1CC is set it first stops playback outright if gp-0x53B0 is non-zero, otherwise it calls the decoder step FUN_002380A8(player 0x002FB308, frame delta gp-0x4C8C) and, when that does NOT return 1, immediately re-opens the same file with FUN_00237AD8(0x002FB308, manager+0x1E4). The listing is explicit: `jal 0x002380a8` then `xori v0,v0,1` and `beq v0,zero,skip`, so only a return of exactly 1 skips the re-open. Re-opening restarts the stream from the beginning, which is the original's looping mechanism; there is no play-once branch and nothing clears the cached path except an explicit stop or a different movie being requested. The front end therefore plays its background movie continuously.
